# Forma — AI Workspace MCP Server

Локальное рабочее пространство для AI-клиентов: MCP-инструменты создают интерактивные задачи, графики, документы, код, таблицы и тесты в React-панели. Изменения сохраняются в SQLite и передаются браузерам через WebSocket. Для MCP и обычной панели отдельный API-ключ не нужен. Встроенный ассистент использует установленный на этом Mac Codex CLI и его существующую авторизацию. Голос преобразуется в текст средствами браузера.

**Установка на другом компьютере:** [INSTALL_CODEX.md](../INSTALL_CODEX.md). Клонируйте репозиторий и выполните `bash scripts/install.sh`: сборка и регистрация MCP в установленном Codex.

**Статус проверки:** backend, production-сборка, unit/integration/race-тесты и реальные MCP-вызовы независимого SDK проверены. После запуска сервера пользователем проверены настоящий Codex, импорт локального изображения и отображение на панели без перезагрузки. Автоматизированные браузерные сценарии используют явно обозначенные mocks; физический микрофон отдельно не проверен. Подробности — [TESTING.md](../TESTING.md).

## Возможности

- 28 MCP-инструментов, строгие схемы и общий сервис для MCP, REST и WebSocket.
- STDIO и аутентифицированный Streamable HTTP `/mcp`.
- Рабочие пространства, вкладки, grid/list, темы light/dark/system, поиск, уведомления.
- Шесть типов проверяемых математических задач; точные дроби и эквивалентные ответы.
- Line/bar/pie/scatter, таблицы с поиском и сортировкой, безопасный Markdown, код с подсветкой и копированием, интерактивные математические тесты.
- Локальные фото и галереи, видео/аудио, PDF-вложения, чек-листы, показатели и прогресс — всего 15 типов виджетов.
- Автосохранение, миграции SQLite, последние 100 событий каждого пространства, история попыток.
- Heartbeat, reconnect с обновлением браузерной сессии, снимок состояния, версии, несколько вкладок, отключение медленных клиентов.
- Frontend встроен в Go-бинарник через `go:embed`; отдельный Node-процесс в production не нужен.

## Требования

- Go **1.26.5 или новее** (проверено на установленной 1.26.5; обновление toolchain в sandbox недоступно).
- Node.js 22.12+ (или 24+), npm.
- CGO, C-компилятор и SQLite 3.24+ с заголовками. На macOS — Command Line Tools (`xcode-select --install`); SQLite входит в систему. На Linux понадобятся пакеты компилятора и `libsqlite3-dev` соответствующего дистрибутива.
- Современный браузер с MathML Core и ES2023 (актуальные Chrome, Safari, Firefox).
- Для E2E: Google Chrome либо установленный Playwright Chromium с изменением `channel` в `playwright.config.ts`.

Go-модули сторонних библиотек не требуются. Frontend-зависимости зафиксированы lock-файлом. Ссылки на npm tarball и несколько overrides используются для воспроизводимой установки из доступного офлайн-кэша.

## Быстрый запуск

```bash
npm ci
make build
./ai-workspace
```

Откройте **http://localhost:8080** или **http://127.0.0.1:8080**. По умолчанию приложение слушает только `127.0.0.1:8080`. Создайте виджет кнопкой на панели либо подключите MCP-клиент.

Эквивалентная ручная сборка:

```bash
npm run build
go build -o ai-workspace ./cmd/server
./ai-workspace
```

Vite создаёт `web/dist`, даже если каталога нет. `make build` всегда собирает frontend раньше Go; сборка Go без frontend намеренно не считается production-сборкой. Маркер `web/dist/.keep` позволяет запускать backend-тесты в чистом checkout. Если dist отсутствует до backend-тестов: `mkdir -p web/dist && touch web/dist/.keep`.

После сборки можно перенести бинарник в другой каталог. При запуске он создаст `.ai-workspace/` относительно рабочей директории. Встроенные ресурсы не зависят от текущего каталога. Для стабильного расположения базы используйте абсолютный `--data-dir`.

SQLite подключена как системная библиотека: frontend поставляется внутри одного исполняемого файла, однако бинарник **не является полностью статическим**. На целевой машине нужна совместимая SQLite. Windows и кросс-компиляция в этой среде не проверены.

## Разработка и команды

```bash
make dev         # Go HTTP :8080 + Vite HMR :5173
make build       # typecheck → Vite → Go binary
make test        # unit/integration + race + TypeScript
make lint        # go vet + ESLint
make run         # build и запуск
make clean       # только генерируемые артефакты; данные сохраняются
make e2e         # build + Playwright, нужен доступный loopback
npm run test:mcp # официальный независимый MCP SDK, STDIO + рестарт
make test-http   # официальный SDK → настоящий Go HTTP handler через IPC

```

Vite проксирует `/api` и `/ws` к backend. В production используется только встроенная сборка. Дочерние процессы dev-режима завершаются вместе с launcher.

## Конфигурация

Приложение читает переменные окружения и флаги. Флаги имеют приоритет. `.env` автоматически не загружается; пример — [.env.example](../.env.example).

| Флаг | Переменная | По умолчанию |
|---|---|---|
| `--transport` | `WORKSPACE_TRANSPORT` | `http` |
| `--addr` | `WORKSPACE_ADDR` | `127.0.0.1:8080` |
| `--data-dir` | `WORKSPACE_DATA_DIR` | `.ai-workspace` |
| — | `WORKSPACE_TOKEN` | генерируется и сохраняется в `DATA_DIR/mcp-token` |
| `--dashboard=false` | — | HTTP включён; отключение разрешено только для headless STDIO/CI |

HTTP-панель запускается в обоих обычных режимах. `--dashboard=false` нужен для работы STDIO в средах, где запрещён `listen(2)`, и для независимых протокольных тестов. Флаг не используется при обычном подключении с панелью.

Токен содержит минимум 32 символа, не выводится в логи и не передаётся в URL. Сгенерированный файл создаётся с правами `0600`, каталог данных — `0700`. Если задан `WORKSPACE_TOKEN`, файл токена не используется. Не помещайте секрет в TOML/исходники; передавайте его переменной окружения.

## Подключение Codex

Формат проверен по `codex mcp add --help` установленного **Codex CLI 0.167.1** и [официальной документации OpenAI](https://developers.openai.com/codex/mcp). Для автоматической локальной установки используйте [INSTALL_CODEX.md](../INSTALL_CODEX.md). Независимый официальный MCP TypeScript SDK проверяет STDIO и HTTP-протокол через IPC-мост к настоящему Go handler. Интеграция встроенного ассистента с настоящим Codex отдельно проверена на запущенном пользователем сервере.

### STDIO

Остановите уже запущенный экземпляр на :8080, чтобы Codex мог занять порт. Используйте абсолютные пути:

```bash
codex mcp add ai-workspace -- \
  /absolute/path/ai-workspace --transport stdio \
  --data-dir /absolute/path/workspace-data
codex mcp list
```

Тот же формат в `~/.codex/config.toml`:

```toml
[mcp_servers.ai-workspace]
command = "/absolute/path/ai-workspace"
args = ["--transport", "stdio", "--data-dir", "/absolute/path/workspace-data"]
```

Codex запускает один процесс; HTTP-панель запускается вместе с ним. Протокольные сообщения идут в stdout, структурированные логи — только в stderr. Завершение stdin или SIGTERM останавливает сервер с graceful shutdown.

### Streamable HTTP

Сначала запустите `./ai-workspace` в отдельном терминале. В том терминале, из которого запускается Codex:

```bash
export WORKSPACE_TOKEN="$(cat /absolute/path/workspace-data/mcp-token)"
codex mcp add ai-workspace \
  --url http://127.0.0.1:8080/mcp \
  --bearer-token-env-var WORKSPACE_TOKEN
codex mcp list
codex
```

Или конфигурация:

```toml
[mcp_servers.ai-workspace]
url = "http://127.0.0.1:8080/mcp"
bearer_token_env_var = "WORKSPACE_TOKEN"
```

Переменная должна быть доступна процессу Codex. При использовании файла сгенерированного токена убедитесь, что путь соответствует выбранному `--data-dir`. Для стандартного запуска это `.ai-workspace/mcp-token`.

`/mcp` требует Bearer при каждом запросе. Браузерная cookie не авторизует MCP. Поддерживаются версии протокола `2025-11-25`, `2025-06-18`, `2025-03-26`. POST возвращает JSON; GET возвращает допустимый спецификацией `405`, поскольку сервер не предлагает MCP SSE. Сессии имеют время жизни 1 час без активности. WebSocket панели является отдельным каналом, не MCP-транспортом.

### Демонстрационные команды Codex

- «Создай математическую задачу средней сложности и покажи её на панели».
- «Покажи график функции y=x² от −10 до 10».
- «Создай таблицу с планом исследования».
- «Очисти рабочую область».
- «Добавь вкладку “Алгебра”».

AI должен сначала получить ID существующего виджета через `widget_list`/`workspace_get_state`, если ID ещё неизвестен. Очистку и удаление применяйте только по запросу пользователя.

## Хранение и безопасность

Единица доступа — **локальная установка одного владельца**. Все её рабочие пространства доступны локальному пользователю панели и клиентам с общим Bearer-токеном; изоляция по workspace ID применяется к состоянию и подпискам. Многопользовательские роли, отдельные токены пространств и удалённый доступ не реализованы. Доступ по `0.0.0.0`/публичному адресу запрещён независимо от конфигурации.

Браузер при открытии локальной панели получает HttpOnly/SameSite=Strict cookie через `/api/session`. Это намеренная модель доверия локальному владельцу, а не login для удалённого сервиса. Host и Origin проверяются по точному локальному адресу/порту; cross-site запросы отклоняются, мутации REST требуют нестандартный заголовок и JSON. WebSocket требует разрешённый Origin и cookie либо Bearer. CORS не открыт. CSP запрещает сторонние скрипты, iframe и объекты.

Данные AI никогда не интерпретируются как HTML или JavaScript. Markdown, MathML и подсветка кода создают React-узлы с автоматическим экранированием. Правильные ответы не включаются в публичные снимки; шаги решения появляются только после явного раскрытия. Генерация и проверка выполняются на сервере.

Ограничения: 1 MiB на команду, 8 MiB на workspace, 200 виджетов, 20 вкладок, 50 пространств, 500 точек/строк, 100 попыток на вопрос, 128 WebSocket и 256 MCP-сессий. История сохраняет последние 100 событий пространства, включая публичные снимки. Очистка/удаление убирают активное содержимое, **но недавняя история остаётся в SQLite**. Для резервной копии завершите сервер и скопируйте каталог данных. SQLite WAL и synchronous=FULL защищают подтверждённые транзакции.

Один процесс держит эксклюзивную файловую блокировку базы. Второй экземпляр с тем же data-dir завершится ошибкой, предотвращая расхождение кешей. Несколько браузеров и MCP-клиентов одного процесса поддерживаются.

## Известные ограничения и отличия от исходного задания

1. Официальный Go MCP SDK скачать не удалось: сеть sandbox отключена. Реализован собственный ограниченный MCP transport; он проверен официальным независимым SDK. Замена адаптера не требует изменения бизнес-логики.
2. KaTeX недоступен в офлайн-кэше. Используется MathML Core и безопасное подмножество LaTeX генератора (`frac`, степени, `times`, `text`, системы). Произвольный LaTeX и макросы не поддерживаются.
3. Вместо Recharts используются интерактивные SVG-графики; вместо Zustand — типизированное хранилище на `useSyncExternalStore`; компоненты диалога — Radix UI. Нативные графики поддерживают клавиатурный фокус, подписи и табличные данные.
4. Markdown поддерживает заголовки, абзацы, списки, цитаты, fenced code, inline code/emphasis/ссылки. Это не полный CommonMark/GFM: Markdown-таблицы, изображения и вложенные списки не реализованы. Для таблиц используйте TableWidget. Подсветка кода лексическая, без полноценного языкового анализатора.
5. Генератор использует шаблоны и точные рациональные ответы. Не поддерживает произвольные пользовательские уравнения, символьную алгебру, приближённую проверку, смешанные дроби или запись корней через радикалы. Системы принимают числа в порядке x,y либо `x=…; y=…`.
6. Полный браузерный E2E, реальный TCP HTTP и подключение активного Codex app-server требуют запуска вне текущего ограниченного sandbox. Приложенные тесты не помечены фиктивным успехом.
7. Public hosting, OAuth, роли, терминал, редактор кода и несколько агентов не входят в эту версию. Встроенный ассистент использует установленный локально Codex; отдельный OpenAI API key не нужен. Архитектура расширения описана в [ARCHITECTURE.md](../ARCHITECTURE.md).

## Встроенный ассистент: ваш локальный Codex

Панель отправляет текст **установленному на ноутбуке Codex**, через официальный `codex app-server` по STDIO ([документация](https://learn.chatgpt.com/docs/app-server)). Отдельный `OPENAI_API_KEY` и OpenAI Realtime больше не используются. Codex сохраняет свою авторизацию и настройки модели; доступ и лимиты зависят от аккаунта Codex. Это отдельный диалог для каждого workspace, а не скрытый ввод в открытый чат приложения Codex.

```bash
codex --version
codex login status
# Если вход ещё не выполнен:
codex login
make build
./ai-workspace --transport http
```

Откройте http://localhost:8080 и **обновите страницу после перезапуска старого сервера**. В Forma AI отображается локальный Codex. Начните с текстовой команды «Создай математическую задачу», затем «Сделай её сложнее» и «Покажи решение». Состояние панели обновляется по прежнему WebSocket. Backend передаёт 26 инструментов общего сервиса как dynamic tools Codex, без второго набора бизнес-правил. Отдельный app-server запускается по первой команде; его авторизацией управляет сам Codex. Конфигурационные файлы Codex приложение не переписывает.

Путь CLI при необходимости задаётся через `WORKSPACE_CODEX_BIN=/absolute/path/to/codex`. Процесс наследует окружение сервера, кроме `OPENAI_API_KEY`. Codex runtime DB/logs размещаются в `DATA_DIR/codex-runtime`; `CODEX_HOME` не переназначается. При запуске через Finder/PATH без Codex укажите абсолютный путь или запускайте сервер из своего терминала.

### Голосовой ввод

1. Нажмите микрофон и разрешите доступ к микрофону/распознаванию речи для сайта в браузере и macOS.
2. Произнесите команду. Промежуточный текст показывается в панели. После **четырёх секунд тишины** фраза автоматически отправляется Codex. Само событие final больше не запускает обработку: короткие фразы и перезапуски распознавателя объединяются. В настройках выберите паузу **2–10 секунд**; кнопка «Отправить фразу сейчас» отправляет накопленный текст сразу. При ручном выключении микрофона уже распознанный текст отправляется; завершение сессии отменяет незавершённую фразу. До трёх следующих голосовых команд могут ожидать окончания текущего ответа.
3. Ответ приходит текстом в историю и системным уведомлением macOS. Озвучки нет.
4. Повторное нажатие останавливает распознавание; «Завершить сессию» также отменяет выполняющуюся команду. «Прервать» отменяет ход Codex.

Используется Web Speech API в поддерживаемых Chrome/Safari. **Это не обещание локального/offline ASR:** браузер может отправлять аудио своему сервису распознавания и требовать сеть. Если сервис недоступен, разрешение запрещено или браузер не поддерживает API, появляется конкретная ошибка. Можно использовать встроенную диктовку macOS в поле команды и нажать отправку. Аудио не отправляется приложением в OpenAI Realtime и не сохраняется Go-сервером. [Ограничения browser recognition](https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition).

### Интернет и изображения

Для диалога Codex включён `web_search=live`; фактическая доступность поиска зависит от установленной версии, модели и политик аккаунта. Ассистент получает возможности локального Codex, а не ограниченный Realtime function loop. Поиск не означает автоматическое наличие произвольного плагина или инструмента генерации изображений.

Изображения теперь поддерживают как публичные HTTPS, так и локальные адреса хранилища Forma. Сгенерированный файл **не нужно публиковать в интернете**.

**Из браузера:** «Добавить виджет» → перетащите файлы или «Выбрать файлы». Для нескольких фотографий включите «Собрать фотографии в галерею». Изображение можно увеличить; аудио/видео имеют обычные элементы управления, PDF доступен для скачивания.

**Из Codex/MCP:** инструмент `media_import` принимает локальный путь, копирует файл в постоянное хранилище и по умолчанию сразу создаёт подходящий виджет:

```json
{"path":"/Users/your-name/.codex/generated_images/example/image.png","title":"Мой чертёж","alt":"Чертёж детали"}
```

Пути в примере иллюстративные: передайте действующий абсолютный путь. Возвращаются `asset` с локальным URL `/api/media/{workspace}/{sha256}` и созданный `widget`. Для галереи импортируйте с `attach:false`, затем создайте `type:gallery` с массивом `{url,alt,caption?}`. Инструкции встроенного Codex уже предписывают размещать созданную картинку через этот инструмент.

По умолчанию импорт разрешён из рабочей директории сервера и `~/.codex/generated_images`. Для других каталогов задайте дополнительные **абсолютные** пути через `WORKSPACE_MEDIA_IMPORT_ROOTS`, разделённые `:` в macOS/Linux. Symlink за пределы разрешённого каталога блокируется через `os.OpenRoot`. Файловый диалог браузера позволяет явно выбрать файл без расширения серверных прав на папки.

Поддерживаются PNG, JPEG, GIF, WebP, MP4/WebM, MP3/WAV/OGG/M4A и PDF. До **25 МБ на файл**, до **200 файлов / 250 МБ на workspace**; растровые изображения — до 40 Мп. HEIC, SVG, произвольный HTML и исполняемые файлы не поддержаны. Проверяется фактическое содержимое, а не доверенный MIME из браузера. Файлы сохраняются в `DATA_DIR/media`, метаданные — в SQLite. Для бэкапа копируйте весь каталог данных. Исходный файл можно переместить после импорта: панель использует собственную копию.

Выдача файлов требует прежнюю cookie/Bearer-авторизацию и проверяет workspace. PDF выдаётся как attachment, имена скачивания нормализуются под формат. Загруженный HTML/SVG не исполняется. Удаление карточки или очистка пространства **не удаляет сохранённые файлы**; сборщик мусора пока не реализован. При лимите места расширение/очистка хранилища остаётся административной операцией, автоматического удаления пользовательских файлов нет.

Новые типы доступны через `widget_create`/`widget_update`: **gallery, video, audio, file, checklist, metric, progress**. Чек-лист сохраняет отметки, показатель хранит значение/единицы/изменение, прогресс — 0–100%. Примеры и строгие схемы: [MCP_TOOLS.md](../MCP_TOOLS.md).

### Контекст, сохранение и подтверждения

Для workspace хранится свой Codex thread ID. Следующие команды продолжают этот диалог; после перезапуска используется `thread/resume`. При изменении каталога инструментов создаётся новая ветка Codex с обновлёнными схемами и ограниченным контекстом прежнего диалога: старые HTTPS-only ограничения не остаются в кэше. К каждому ходу добавляется ограниченный контекст текущей вкладки, последнего виджета и состояния панели. Новые команды при активном ходе отклоняются явно, а не запускаются параллельно. Смена пространства закрывает микрофон и отменяет ход предыдущего пространства.

Очистка/удаление проходят прежний nonce + version check в общем router и требуют кнопки подтверждения. Запросы Codex на выполнение команд с доступным полным кратким preview показываются для явного разового подтверждения. Запросы файловых изменений и неподдерживаемые интерактивные запросы отклоняются; файлового diff-review в панели пока нет. По умолчанию Codex thread запускается с read-only sandbox. Никаких автоматических одобрений shell/file actions нет.

Время выполнения команды Codex не ограничено: ход продолжается до завершения, ручной отмены, разрыва соединения или остановки приложения. Лимиты: четыре одновременно загруженных активных процесса Codex (неактивные освобождаются), две минуты на подтверждение, 8000 символов запроса/ответа. Request ID резервируется в SQLite до выполнения; повтор не запускает команду снова. Неизвестный исход после падения требует проверки панели. Сохраняются последние 2000 receipts; повтор очень старого удалённого ID может считаться новым запросом.

Настройки языка, уведомлений и истории сохраняются в SQLite. При отключении истории новый Codex thread создаётся ephemeral, полный ответ не включается в durable request receipt; сообщения текущей сессии остаются в памяти. Ранее сохранённые Codex rollouts не удаляются автоматически. История workspace, результаты инструментов и политика облачного хранения аккаунта Codex существуют отдельно от настройки сообщений.

### Системные уведомления macOS

Ответ отправляет Go-сервер через встроенный `/usr/bin/osascript`, без запрошенного звука, после подтверждённого завершения хода. Полный текст остаётся в истории; баннер ограничен 400 символами. Есть очередь, лимит 30/мин и дедупликация ID. Стиль и длительность баннеров задаёт macOS; отправителем может показываться Script Editor / Редактор скриптов. Своего подписанного app bundle с иконкой пока нет.

Проверка без Codex/API-ключа: **Forma AI → Настройки → Проверить уведомление macOS**, или:

```bash
./ai-workspace --notify-test
```

В macOS разрешите баннеры для Script Editor и проверьте «Фокусирование». Submitted подтверждает отправку команды ОС, не гарантирует видимость баннера. `ui_show_notification` тоже отправляет системное уведомление, сохраняя прежнюю карточку панели. Баннер возникает на Mac, где работает Go-процесс.

### Проверка настоящего Codex без HTTP

```bash
./ai-workspace --codex-check --data-dir .cache/codex-check
```

Это **реальный вызов модели через ваш Codex**, который создаёт тестовую математическую карточку в отдельной SQLite. Нужны выполненный `codex login` и доступ к сервису Codex. Автоматические тесты используют отдельный subprocess fixture; его ответы не выдаются за настоящую модель. Точные результаты, включая ограничения текущей sandbox и проверку голоса, описаны в [TESTING.md](../TESTING.md).
