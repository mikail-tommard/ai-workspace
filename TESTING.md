## Unit и integration

```bash
go test ./...
go test -race ./...
go vet ./...
npm run typecheck
npm run lint
npm run build
```

`make` использует `GOCACHE=$PWD/.cache/go-build`, чтобы не писать в системный каталог кеша. При запуске Go вручную в ограниченной среде можно задать тот же `GOCACHE`. На обычной машине это не требуется.

Покрытие сценариев:

- **Math Engine:** по 200 генераций каждого из 6 типов на 3 уровнях — 3600 задач; самопроверка правильных и неправильных ответов; эквивалентные дроби/десятичные записи; порядок корней, координаты систем; недопустимые типы/уровни/числа.
- **Workspace/Dispatcher:** каждый из 27 инструментов вызывается тестом с осмысленными параметрами, ошибочные команды не меняют версию; вкладки, layout/theme, лимит карточек, изоляция пространств, 40 одновременных мутаций, закрытие медленной подписки, повторный unsubscribe.
- **Registry/Validation:** запрет неизвестных полей, типов, выходящих за границы чисел, неверной ширины таблицы и отрицательных pie-значений.
- **Storage:** настоящая SQLite, миграции, эксклюзивная файловая блокировка второго открытия, повторное открытие базы, идентичность состояния после рестарта, сохранение попыток и откат при duplicate event. Проверяется отсутствие приватных expected в публичной истории.
- **MCP:** initialize, initialized, tools/list, tools/call, ошибки аргументов/методов, корректный stdout, HTTP session lifecycle, GET 405, DELETE, Origin/auth/content type/protocol version, structuredContent.
- **REST:** команды, состояние, история, каталог схем, auth, CSRF/Origin/Host, неизвестные поля, лишний JSON, SPA fallback и 404 для отсутствующего asset.
- **WebSocket:** настоящий handshake и кадры RFC6455, начальный снимок, два одновременных клиента, доставка мутации, reconnect snapshot, входящая WS-команда.

`net.Pipe` заменяет только OS TCP socket. Тесты запускают `net/http.Server` с listener в памяти и обычный `http.Transport`; запросы проходят настоящий HTTP parser и WebSocket upgrade. Это даёт интеграционную проверку логики и framing, но не подтверждает работу DNS, OS sockets и браузера вместе с сервером.

## Независимый MCP-клиент

```bash
make build
npm run test:mcp
```

[scripts/mcp-smoke.mjs](scripts/mcp-smoke.mjs) использует официальный `@modelcontextprotocol/sdk`, запускает **скомпилированный бинарник** по STDIO с `--dashboard=false` и отдельной временной БД. Он проверяет handshake и 27 схем, создаёт задачу, вычисляет ответ из её уравнения независимо от сервера, проверяет ответ и решение, создаёт четыре вида графиков и таблицу, проверяет ошибочную команду. После закрытия/повторного запуска процесса сравнивает полные публичные состояния.

Этот тест работает без TCP и без доступа к AI API. Успех проверяется assert, а не фиктивным ответом сервера. Каталог временных данных выводится для диагностики; пользовательская база не затрагивается.

## Независимая проверка HTTP MCP без TCP

```bash
make test-http
```

`cmd/httpbridge` — отдельный тестовый IPC harness, не production entry point. Он принимает обычный HTTP-конверт по stdin, вызывает настоящий `App.Handler()` через `httptest.ResponseRecorder` и возвращает статус/заголовки/body. [scripts/http-mcp-smoke.mjs](scripts/http-mcp-smoke.mjs) подставляет этот обмен как Fetch в официальный `StreamableHTTPClientTransport`. MCP-ответы и бизнес-логика не подменяются.

Пройдены: initialize, session header, initialized, обнаружение 27 инструментов, реальное создание задачи, строгая ошибка параметров, чтение состояния и DELETE сессии. Этот результат подтверждает совместимость протокольного HTTP-адаптера с независимым SDK, но не запуск TCP-сервера.

## Исправление: голос распознан, но текстового ответа нет

Причина: continuous SpeechRecognition мог оставлять результат промежуточным; старый обработчик отправлял только isFinal. Переключено на отдельные фразы. speechend завершает распознавание; onend отправляет оставшийся текст, есть bounded fallback для отсутствующих final/end. Поздний final не создаёт дубликат. Ручное выключение микрофона отправляет распознанную фразу, а dispose/подтверждение/завершение отменяют её. До трёх голосовых команд ожидают текущий ответ вместо потери при busy. Backend сохраняет принятую команду до запуска Codex; даже ошибка старта теперь оставляет видимый пользовательский текст. Пустой ответ после подтверждённого tool-only хода получает текстовую квитанцию по реальному результату инструментов, а не фиктивный успех.

Дополнительные тесты (всего 15 frontend): interim→end без final, speechend→late final без дубликата, ручной stop vs dispose, стабильный interim без final/end, очередь при busy. Backend проверяет запись команды при startup failure и текстовый ответ после tool-only turn. Race detector и production build прошли.

**Живая проверка — PASS:** в отдельном workspace «Проверка голосового ввода · 08:02» production frontend обращался к настоящему Go HTTP/WebSocket/SQLite и установленному Codex с существующей авторизацией. Подставлялись только browser recognition interim/end events, без final. Фраза «Сколько будет 17 плюс 25? Ответь одним числом» дала настоящий ответ Codex **42**; следующие фразы создали линейную задачу и повысили её сложность с прежним widget ID. Текст появился в истории. Физический микрофон и vendor ASR не подменяются этим результатом и не заявляются проверенными.

Для проверки свежего frontend без остановки пользовательского процесса в тестовой странице маршрутизировались только production JS/CSS-файлы с диска; API и WebSocket шли на реальный сервер без mocks. Маршрутизация самого HTML в первой попытке привела к browser local-network-check запрету WebSocket; после сохранения настоящего HTTP-документа тест прошёл. Тестовая карточка оставлена в отдельном QA workspace; основной диалог не менялся. Чтобы обновление заработало в обычной вкладке, требуется перезапустить собранный бинарник с embed-ресурсами и обновить страницу.

## Локальные файлы, семь новых виджетов и длинная пауза

Финальный прогон расширения: `make build`, `make test` (go test ./..., go test -race ./..., strict TypeScript, **18 frontend tests**), `make lint`, `npm run test:mcp`, `make test-http` — **PASS**. Теперь проверяется 28 MCP-инструментов. Новый media_import включён в TestAllTools; прежние 27 инструментов сохранены.

Backend проверяет реальные копии PNG, SHA-256, импорт/attach=false, разрешённые корни, symlink escape, workspace isolation, перезапуск SQLite и повторное открытие файла. Проверяются поддельные HTML/SVG под расширением PNG, небезопасные download-имена, отмена, закрытые схемы галереи/аудио/видео/файла, уникальные ID чек-листа и диапазон прогресса. Все семь новых типов создаются через общий service и восстанавливаются после перезапуска. HTTP тест проверяет настоящую multipart-загрузку, cookie/Bearer/Origin, точные байты PNG, Content-Type и закрытый доступ. IPC bridge сохраняет двоичные request/response в base64, не повреждая данные преобразованием UTF-8.

Независимый официальный MCP SDK реально вызывает media_import через STDIO и получает приватный asset URL. HTTP SDK-тест дополнительно загружает PNG через FormData и сравнивает скачанные байты с оригиналом.
